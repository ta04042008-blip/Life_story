# シナリオ別イベント仕様 v0.1

## 収録物

| ファイル | 内容 |
|---|---|
| data/events-initial.json | 基本原稿24件、選択肢49件、年齢・利用条件・数値効果・性格タグ |
| data/scenario-bindings.json | 10シナリオの文脈、原稿240件、対象人物・制度条件への対応 |
| data/event-outcomes.json | 選択の結果24契約、状態遷移、後日談、保存・再開時の処理契約 |

いずれもゲーム仕様の原稿・構造データ。イベントを動かすエンジンや歴史統計そのものは含まない。条件や原稿の対応が書かれていることと、実際に正しくプレイできることは別に確認する。

## 1. 文化圏への対応

| シナリオ | 今回の文脈 | 学び・生業の扱い |
|---|---|---|
| jp_historical | 江戸期の東北農村 | 家の農作業、近隣の集落、身近な学び・手仕事 |
| cn_historical | 清代の都市生活 | 家の生業、町の仕事、文字・知識を教わる場 |
| in_historical | ムガル期の北インドの町と周辺 | 家の生業、利用可能な学びや修業 |
| ml_historical | トンブクトゥ・ニジェール川交易圏 | 川と町の暮らし、読み書き、生業の伝授 |
| fr_historical | 近世フランスの町と周辺農村 | 家の生業、町や村での学びや修業 |
| jp_modern | 現代日本 | 利用可能な学校・学習、職、世帯・地域 |
| cn_modern | 現代中国 | 同上。地域・世帯・制度条件を個別に参照 |
| in_modern | 現代インド | 同上。国平均だけで利用可能性を決めない |
| ml_modern | 現代マリ | 同上。資料不足は推定として記録 |
| fr_modern | 現代フランス | 同上。地域・世帯・制度条件を個別に参照 |

これは原稿の舞台設定であり、住民全員の家業・教育・家族像を固定しない。学校や修業の具体名、学費、就学率、婚姻の形などは、史料で確認できる範囲を使い、不足分は根拠・幅・信頼度を記録したゲーム用推定としてデータ化する。未確認の利用条件はfalseとして扱う。同じ国でも都市・農村、世帯資源、言語、社会的制約によって候補を変える。

出生舞台の `period` は初期文脈の適用範囲で、人生の打ち切り年ではない。存命中は暦年に合わせて社会状況を更新する。後続年代に直接の資料が乏しい場合は、変化の筋が通る範囲で根拠・幅・信頼度を記録したゲーム用推定や予測を用いる。史料不足だけを理由に公開を止めず、継続する社会状況を定義できない場合に限り、そのシナリオの公開を保留する。各指標の出典が予測とする年は、公表予測と予測終端後のゲーム用仮説を区別して用いる。

## 2. 対象人物と選択の成立条件

イベント生成時に家族・友人・師などの人物IDを解決し、決断とともに保存する。読み込み時に別の人物を再抽選しない。対象人物や制度がなくなった場合は、交流できている体で描かず、状況を再確認して候補を作り直す。

行動が成立するには、テンプレート・シナリオ・機会データの全条件が必要。子どもだから学校がある、ある国だから特定の家族形態である、といった判定をしない。選択肢が2件未満になったイベントは提示せず、実行可能な生活方針へ戻す。

養育者が判断するイベントでは actor_id を養育者として保持する。性格は主人公自身が判断した行動だけに加算し、養育者の判断を主人公の性格へ加えない。おまかせの実行者・根拠は別に記録する。

## 3. 大きな決断の状態変化

| 決断 | 受け入れたとき | その後に確かめること |
|---|---|---|
| 進学 | 在籍先、開始時期、期間を保存 | 学びの負担、生活、仲間。進路を見送った場合は別機会も残す |
| 修業 | 技能、契約、師、期間を保存 | 進捗と師との関係。修了は別の条件で判断 |
| 就職 | 新契約の確定と旧契約終了を同じ処理で行う | 実際の収入・負担。賃金は契約データで定義 |
| 移住 | 準備を開始し、出発・到着を予定として保持 | 住居、同行者、仕事、関係。移住決断直後に所在地を瞬間変更しない |
| 共同生活 | 双方の意思と成立条件を確認し、世帯構成を更新 | 役割分担と生活。資源の表示値を単純加算しない |
| 療養 | 病状に療養計画を結び付ける | 改善・継続・悪化。死亡抽選を基準モデルと二重に行わない |

機会の辞退後も同じ機会を繰り返し提示しない。別の学校・仕事・移住先・病気の再発など、別機会IDであれば人生の後半にも同じ分類の決断が起きる。

## 4. 後日談

日常18件は2四半期後を初期設定に、当時の行動と現在の状態を振り返る短い記録を持つ。大きな決断は2四半期後、進路の見送りは4四半期後、移住・療養は契約の移動期間・評価時期に応じて記録する。

後日談は元の数値効果をもう一度付ける仕組みではない。元決断IDと後日談IDを保存し、1回だけ記録する。相手の死別や活動の中断があれば、現在も続いている体で文章を出さない。

療養の改善率や進路の修了率は、この原稿だけから作らない。利用する病状モデル・契約・試験に応じたデータが必要。初期の療養選択にあった無条件の健康+2は結果契約で置き換え、経過に応じた結果処理へ移した。

## 5. 実行時の一貫性

1. 決断候補、対象人物、機会と既定の選択肢を生成して保存。
2. 回答時に条件を再確認。
3. 回答IDで重複処理を防止。
4. 数値、所属・世帯・所在地、予定、履歴をまとめて確定。
5. 未完了なら元の状態を保持し、確定後に保存。

ファイル内の `$offer` などはイベントデータ参照の記法で、自由なコード実行を意味しない。実装は定義済みの参照と操作だけを読み取る。

## 6. 今回できた範囲と公開までに必要な作業

文化圏ごとの文脈、24件の原稿と結果のつながりは作成済み。国・文化圏の平均を個人の能力へ直結させる処理は設けていない。

具体的な社会層・出生比率、史料の適用範囲、教育・雇用・病状のデータ、後続年代のデータ、エンジン実装と通しプレイは未完了。240件は共通24件の文化圏別表現であり、240種類の独立した出来事ではない。学生期から30代の連続的な人生を十分に描くには、進路・学友・仕事・関係の継続イベントを追加する必要がある。
