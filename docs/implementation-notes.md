# 実装メモ

## 技術選択
- フレームワークなしのES Modules（バンドラ不要）。ブラウザ（fetch）とNode（テスト）で同じ `src/sim` が動く。
- 乱数は sfc32（シードは splitmix32 で展開）。状態4値と抽選回数を人生に保存する。
- 四半期は状態機械 `idle → small → majors → finish`。未回答の決断は全文を保存し、回答は `life.resolutions` と決断IDで一度だけ反映（失敗時はスナップショットへ戻す）。
- 結果契約（`event-outcomes.json`）の `state_operations` は固定の演算（set / append / consume / ensure_relationship / schedule / end / apply_household_plan）だけを解釈する。任意コードは実行しない。

## 仕様の解釈と記録（仕様のJSON例と文章が食い違う箇所・曖昧な箇所）
1. 舞台の`period`と`historical-scope.md`の年範囲：JSONの`period`を採用。
2. 死亡表は性別を区別しない（both sexes）。
3. おまかせは小さな選択と大きな決断で別設定（既定：日常ON／決断OFF）。
4. 汎用舞台の人名は架空の音の組み合わせ。実在の命名慣習を主張しない。
5. 実際の資産単位は扱わず、世帯の暮らし向きを0〜100の指標にまとめる。
6. 作り込み舞台の出生比率は `deep_dive_place_share`（0.5）という調整値で決める（仕様に数値がないため）。
7. 国別系列のない地域の1950年以降の死亡は、近い系列または5系列のlogit平均（ゲーム用推定と表示）。
8. 仕様の24イベントでは人生を支えきれないため、追加の日常イベント36件を `data/impl/events-extra.json` に書き下ろした（`origin: implementation_authored`）。
9. 乳幼児（6歳未満）の選択は養育者が決め、性格の証拠に数えない。

## 検証の状況
- 300人規模の自動通しプレイでエラーなし。同一シード再現、毎ステップ保存→復元しても結果が一致、二重回答で状態が変わらないことをテスト。
- 発見・修正したバグ：offer IDの採番順、教育選択での仕事オファー参照、旅の出発タスク、パートナー再提案、NaN遅延（保存で`null`化して復元後に挙動が変わる）、同一四半期で消費済みオファーの能力が残る問題、世帯と主人公の場所オブジェクトの共有。

## 既知の限界
- 近代以前の生まれは約3割が5歳未満で亡くなる（仕様の歴史的推定表どおり）。体験として重い場合は表の調整が必要。
- 追加イベントの文章は広く通用する中立的な書き方で、地域・時代固有の描写は作り込み舞台のイベント以外では薄い。
- 後日談の記録が多く、「記録」パネルの「主な出来事」フィルタで抑えている。
- 数値は初期調整値で、感度確認（頻度・テンポ・バランス）は未実施。公開版のデータ審査（利用条件・地域適合）も未完了。
- 実機のスクリーンリーダーでの確認は未実施（ダイアログ・フォーカス移動・ARIAラベルは実装済み）。
